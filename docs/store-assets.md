# Store marketing assets

Everything on the Play listing that is not the binary — the demo library, the
screenshots, the feature graphic and the promo video — is generated by scripts
in `scripts/` and is reproducible from a clean checkout. This page is the map:
what exists, what to run, and which file to edit when something needs to change.

The two stage-specific runbooks go deeper:

- **[store-screenshots.md](store-screenshots.md)** — how the raw captures are
  shot, and how the three screenshot slots are rendered.
- **[store-promo-video.md](store-promo-video.md)** — how the screen takes are
  recorded, and how the video is cut.

**Nothing here uploads anything.** `eas submit` ships the AAB only; images and
the video URL are pasted into Play Console by hand, per language. That review is
separate from the binary review and needs neither a new `versionCode` nor a new
build.

---

## 1. What gets produced

| Asset | Play slot | Script | Output |
|---|---|---|---|
| Demo library (`.zip`) | — (input to everything else) | `build-demo-backup.ts` | `assets/store/keeptaste-demo{,-pl}.zip` |
| Phone screenshots | Phone, 1080×1920 | `build-store-screenshots.ts` | `assets/store/play/phone/<lang>/` |
| Tablet screenshots | 7" and 10" tablet | `build-store-screenshots.ts` | `assets/store/play/tablet{7,10}/<lang>/` |
| Feature graphic | Feature graphic, 1024×500 | `build-feature-graphic.ts` | `assets/store/play/feature/` |
| Promo video | Video (via YouTube), 1920×1080 | `build-promo-video.ts` | `assets/store/promo/keeptaste-promo-<lang>.mp4` |

Two languages throughout, `en` and `pl`, because the listing is published in
both and a Polish listing showing English recipe titles looks abandoned.

**What is source and what is build output** — the outputs are all git-ignored,
so a fresh clone has none of them and every one is a single command away:

```
source, tracked                          build output, ignored
─────────────────────────────────────    ─────────────────────────────────
assets/app/**/*.jpg      raw captures →  assets/store/play/**   frames
assets/store/*.png       staged photos → assets/store/crops/    dish crops
assets/store/demo-import*.md  recipes →  assets/store/*.zip     demo library
assets/store/screenshot-captions.json    assets/store/promo/raw/*.webm  takes
assets/store/promo-script.json           assets/store/promo/*.mp4       video
```

The raw device captures are the one exception: they are tracked, because
re-shooting them needs an emulator, a restored demo library and a careful eye,
and the README embeds them.

## 2. Prerequisites

| Need | Why | Check |
|---|---|---|
| macOS | `sips` does every JPEG conversion and crop | — |
| Node + `npx tsx` | the build scripts are TypeScript, run directly | `npx --yes tsx --version` |
| Chrome for Testing | renders every still frame; taken from the Playwright cache, **not** installed by this project | `npx playwright install chromium` |
| ffmpeg + ffprobe | video compositing, and reading single pixels off a screencap | `ffmpeg -version` |
| adb + an emulator | capture and recording | `adb devices` |
| A **real build** of the app | the demo library is restored from a `.zip`, which needs `react-native-zip-archive` — absent from Expo Go | — |

There is deliberately no image-processing dependency (`sharp`, ImageMagick,
canvas). Frames are HTML rendered by headless Chrome, which the machine already
has for Playwright, so the marketing pipeline adds nothing to `package.json`.

## 3. The full run

In order, from the repo root. Steps 1–2 are shared by everything downstream.

```bash
# 1. demo content
bash scripts/crop-demo-photos.sh                 # staged photos → dish crops
npx --yes tsx scripts/build-demo-backup.ts       # → keeptaste-demo.zip
npx --yes tsx scripts/build-demo-backup.ts pl    # → keeptaste-demo-pl.zip

# 2. put an emulator into the demo state (per language)
bash scripts/reset-demo-library.sh en

# 3a. stills — capture by hand (docs/store-screenshots.md §2), then render
npx --yes tsx scripts/build-store-screenshots.ts   # 36 frames: 3 forms × 2 langs × 6 screens
npx --yes tsx scripts/build-feature-graphic.ts     # 2 banners

# 3b. video — record, then cut
bash scripts/record-promo-clips.sh en              # 4 takes → promo/raw/en/
npx --yes tsx scripts/build-promo-video.ts         # → promo/keeptaste-promo-{en,pl}.mp4
```

Every build script narrows the same way: bare words select, and selecting
nothing builds everything.

```bash
npx --yes tsx scripts/build-store-screenshots.ts pl tablet10   # one language, one form
npx --yes tsx scripts/build-promo-video.ts en --music-start 42
```

Only step 3a's capture is manual. It stays manual on purpose: a screenshot is a
composition decision (what is on screen, how far it is scrolled, whether the
keyboard is up), and the scripted taps that work for a moving video are exactly
the ones that land a still shot half a scroll off.

## 4. How the scripts are put together

```
                        build-store-screenshots.ts   build-feature-graphic.ts
                        build-promo-video.ts         build-demo-backup.ts
                                    │
              ┌──────────────┬──────┴───────┬──────────────┐
        lib/config.ts    lib/brand.ts   lib/render.ts    lib/cli.ts
        paths, langs,    palette,       headless        selectors,
        capture geometry type, frames   Chrome → image  --flags

                        reset-demo-library.sh   record-promo-clips.sh
                                    │
                         ┌──────────┴──────────┐
                     lib/adb.sh            lib/screen.sh
                     tap, drag, pixel,     every coordinate,
                     wait, app lifecycle   for 1080×2400
```

Each library owns exactly one kind of decision, so a change has one address:

- **`lib/config.ts`** — project facts. Which languages exist, where files live,
  how big a raw capture is and how many rows of system UI sit along its edges.
  Also `capture(lang, screen)`: captures are addressed **by screen id**, never
  by a hand-written path, because the screens are numbered in listing order and
  inserting one renumbers the rest. (A literal `02-recipe-list.jpg` in the
  feature-graphic script survived exactly one such renumbering before it broke.)
- **`lib/brand.ts`** — the marketing look: palette, font stack, the warm
  background, the device frame. Colours are shared, geometry is per-canvas —
  a 1024×500 banner and a 1600×2560 screenshot need the same colours placed
  differently. Deliberately separate from the app's own `constants/theme.ts`;
  the store look is warmer than the app's surfaces.
- **`lib/render.ts`** — HTML → PNG/JPEG through the cached Chrome for Testing.
  The only place that shells out to a browser.
- **`lib/cli.ts`** — argument parsing. An unrecognised word is an error rather
  than a no-op: silently ignoring a typo'd language ships a listing missing half
  its frames, and the script would still have exited 0.
- **`lib/adb.sh`** — everything that talks to a device. The app is a release
  build and not debuggable (no `run-as`, no `adb root`, no pushing a database
  in), so these scripts work the way a person would: tap, then read pixels back
  to find out what happened.
- **`lib/screen.sh`** — every screen coordinate, in one file, for a 1080×2400
  phone with gesture navigation. This is the file to re-measure after a UI
  change, and the header explains how.

## 5. Where to change what

| To change | Edit | Then run |
|---|---|---|
| Screenshot headlines/sublines | `assets/store/screenshot-captions.json` | `build-store-screenshots.ts` |
| Which screens are in the listing, or their order | same file (add/reorder entries) + shoot the capture | `build-store-screenshots.ts` |
| Video scene order, timing, copy | `assets/store/promo-script.json` | `build-promo-video.ts` |
| Feature-graphic tagline / proof points | `COPY` in `build-feature-graphic.ts` | `build-feature-graphic.ts` |
| Demo recipes, cookbooks, shopping list | `assets/store/demo-import{,.pl}.md` | `build-demo-backup.ts`, then re-shoot |
| Brand colours or type | `scripts/lib/brand.ts` | every still script |
| A screenshot's canvas size or crop | `FORMS` in `build-store-screenshots.ts` | `build-store-screenshots.ts` |
| Anything after a UI change that moved controls | `scripts/lib/screen.sh` | the adb scripts |
| Package id, device default, languages | `scripts/lib/adb.sh`, `scripts/lib/config.ts` | — |

A copy change never needs a re-capture or a re-record. That is the point of the
two JSON files: the expensive input (a device recording) and the cheap input
(a sentence) are separated, so fixing a typo is a 40-second rebuild.

## 6. Adding a language

1. `LANGS` in `scripts/lib/config.ts`.
2. A translated demo library at `assets/store/demo-import.<lang>.md`, an entry in
   `LOCALES` in `build-demo-backup.ts` (which also maps cookbook covers, recipe
   photos and the sample shopping list by name, so those need translating too),
   and a `case` for the archive name in `reset-demo-library.sh`.
3. Copy under the new key in both JSON files, and in `COPY` in
   `build-feature-graphic.ts`. Every script fails loudly on missing copy rather
   than falling back to English — a half-translated listing is worse than an
   English one.
4. Captures under `assets/app/<lang>/` and `assets/app/tablet/<lang>/`.

## 7. Failure modes worth knowing

These all failed quietly at least once, which is why each has a guard now:

- **The restore did not take.** `reset-demo-library.sh` ends by checking that the
  cookbook grid is actually full and exits non-zero if not. Without it, the
  first-launch seed (one cookbook, called "Breakfasts") looks close enough to the
  demo library to shoot a whole session against by mistake.
- **A take is shorter than the storyboard asks for.** ffmpeg would freeze on the
  last frame; `build-promo-video.ts` fails with the measured length instead.
- **The emulator is rendering at 6 fps.** Start it with `-gpu host`. The build
  resamples to 30 either way, so a slow emulator does not fail — it just
  produces visibly stuttering scrolls.
- **A missed tap.** Nothing catches this. Watch the takes before building.
- **Brands and legible text in a food photo.** The staged photos carry real
  pasta and honey brands with mangled lettering; `crop-demo-photos.sh` crops them
  out. Check any replacement cover before shipping it — someone else's trademark
  on a store listing is an IP complaint waiting to happen.

## 8. Upload

Per language, in Play Console → Grow → Store presence → Main store listing:

- **Screenshots** — three sections (phone, 7", 10"), 2–8 images each, from
  `assets/store/play/<form>/<lang>/`.
- **Feature graphic** — `assets/store/play/feature/feature-graphic-<lang>.png`.
- **Video** — a YouTube watch URL, not a file. Upload the mp4 to YouTube first
  (unlisted is fine); no ads and no end screens, which Play rejects.
